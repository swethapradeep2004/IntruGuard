# Network Analysis & Prediction Study Guide

This guide breaks down the network logs used in **IntruGuard** and explains how the underlying machine learning model predicts whether a connection is "Benign" or an "Attack."

## 1. Network Log Attributes (Features)

The table columns you see are derived from the **NSL-KDD dataset**, a standard benchmark for network intrusion detection. Here is what each one represents:

| Feature | Description | Importance in Detection |
| :--- | :--- | :--- |
| **src_bytes** | Total bytes sent from source to destination. | Extremely high counts may indicate data exfiltration or massive file transfers. |
| **dst_bytes** | Total bytes sent from destination to source. | High counts could be related to downloading large malicious payloads or server responses in a DoS attack. |
| **logged_in** | Boolean (1 or 0) indicating if the user successfully logged in. | If an "Attack" label appears with `logged_in = 0`, it often suggests an unauthorized access attempt or brute force. |
| **count** | Number of connections targeting the same host in the last 2 seconds. | Used to detect **Scanning** and **DoS (Denial of Service)** attacks (many connections to one target). |
| **srv_count** | Number of connections targeting the same service (e.g., HTTP) in the last 2 seconds. | Helps identify service-specific flooding (like a specific attack on a web server). |
| **dst_host_srv_count** | Count of connections to the same service on the destination host. | A historical view of how often that specific service is accessed by the host. |
| **dst_host_same_srv_rate** | Percent of connections that target the same service on the destination host. | High rates for unusual services can indicate automated probing or specialized malware behavior. |

---

## 2. Prediction Logic (The "Brain")

The prediction you see in the table is generated by a **Random Forest Classifier**.

### How it works:
1. **The Input**: When you upload a CSV, the system extracts the 7 features listed above for every single row.
2. **The Forest**: The model consists of **50 Decision Trees** that were trained on thousands of known "Normal" and "Attack" patterns.
3. **Voting**: Each individual tree looks at the data (e.g., Is `count > 100` AND `src_bytes < 50`?) and gives its own verdict (0 for Benign, 1 for Attack).
4. **Final Result**: The system counts the votes. If the majority of the 50 trees say it's an attack, the label becomes **"Attack"**.

### Mathematical Representation:
While machine learning models are complex, they can be represented by the **Majority Vote** equation:

$$ \hat{y} = \text{mode} \{ T_1(x), T_2(x), \dots, T_{50}(x) \} $$

Where:
- $\hat{y}$ is the final prediction (Attack or Benign).
- $x$ is the row of data (the logs).
- $T_i(x)$ is the individual prediction from the $i$-th tree.

---

## 3. Severity Scoring
- **High Severity**: Assigned whenever the model predicts an **Attack**. This triggers an immediate alert in the dashboard because the signature matches known malicious patterns.
- **Low Severity**: Assigned to **Benign** traffic. This is considered safe, everyday network activity.

## 4. Typical Feature Thresholds (Rules of Thumb)

Since the model is a Random Forest (an ensemble of 50 trees), there is no single "magic number" for an attack. However, my analysis of the 50 trees shows these **Typical Decision Points** (based on median split values):

| Feature | Typical "Attack" Condition | Explanation |
| :--- | :--- | :--- |
| **src_bytes** | **> 655** | Large outbound data flow is often flagged as an attack signature. |
| **dst_bytes** | **> 1,760** | Significant inbound responses often correlate with malicious activity. |
| **logged_in** | **= 0** | Most attacks occur when no valid user is logged in. |
| **count** | **> 12** | Having more than 12 connections in 2 seconds is a strong indicator of scanning. |
| **srv_count** | **< 15** | Ironically, lower service counts combined with high total counts often indicate "stealth" scanning. |
| **dst_host_srv_count** | **> 66** | High repeat access to a single host service is often flagged. |
| **dst_host_same_srv_rate** | **> 0.93** | While seemingly normal, very high rates to specific services can indicate automated exploitation. |

## 5. Web Analysis Log Attributes

Web analysis focuses on **network flow characteristics** typically seen in web traffic (HTTP/HTTPS).

| Feature | Description | Importance in Web Defense |
| :--- | :--- | :--- |
| **Flow Duration** | Duration of the entire communication flow. | Unusually long flows can indicate slow-rate DoS (Slowloris) or data tunneling. |
| **Total Fwd Packets** | Number of packets sent in the forward direction. | High frequency of small packets is a common sign of scanning or botnet activity. |
| **Total Backward Packets** | Number of packets received from the server. | High response volumes can indicate large data leakage or reflected DDoS. |
| **Total Length of Fwd Packets** | Total bytes sent forward in the flow. | Massive payloads in single requests are typical for SQL injection or file uploads. |
| **Fwd Packet Length Mean** | The average size of a packet sent forward. | Changes in average size can indicate encrypted command-and-control (C2) traffic. |
| **Bwd Packet Length Mean** | The average size of packets received back. | Helps differentiate between a simple "OK" response and a large database dump. |
| **Flow Bytes/s** | The throughput rate of the whole connection. | Extremely high throughput is a major indicator of a focused Dos attack. |

---

## 6. Typical Web "Attack" Thresholds

After analyzing the **Web Random Forest model**, here are the typical conditions that trigger an "Attack" verdict:

| Feature | Typical "Attack" Condition | Explanation |
| :--- | :--- | :--- |
| **Flow Duration** | **> 47,731** | Longer than average flows are suspicious in high-speed web environments. |
| **Total Fwd Packets** | **< 10** | Smaller flows are often used for "hit and run" exploitation attempts. |
| **Total Backward Packets** | **> 7** | Attacks that extract data often receive more packets back from the server. |
| **Total Length of Fwd Packets**| **> 195 bytes** | Payloads larger than a standard header often contain malicious code. |
| **Fwd Packet Length Mean** | **> 91 bytes** | Higher average packet size often indicates encoded malicious parameters. |
| **Bwd Packet Length Mean** | **< 143 bytes** | Small, repetitive responses from the server are common during probing. |
| **Flow Bytes/s** | **> 909** | Higher bandwidth usage often points to denial-of-service attempts. |

**Summary:** The Web Model is tuned to look for **low-packet, high-impact** flows that are characteristic of modern web exploits like SQL Injection and Cross-Site Scripting (XSS).
